# Report/Evidence and Moderation acceptance

Scope: member 3 in BaoTin_Master_Plan_v2_5_Members_SMS_URL.md, plus the Gateway, contract and frontend changes required to use that service. Source delivery is distinct from production deployment.

| Requirement | Implementation and proof |
| --- | --- |
| Create from scan; TEXT/URL targets | Optional scanId in ReportModels/Create and the internal Target contract. Threat checks owner, scan type and matching input/URL identity; ReportSecurityTests proves the caller is the JWT subject. ThreatServiceApplicationTests tests foreign ownership, mismatches and rollback. The frontend carries the selected input into the report composer and never submits demo scan IDs. |
| My Reports; details; history | ReportStore owner-scoped queries and stable pagination; ReportWorkflowTests covers owner isolation, snapshot/history and pagination. ReportWorkspace uses the Gateway client for list/detail/create. |
| Idempotency-Key | Owner-scoped UUID reservation, request hash and stored original response in the same transaction. Tests cover replay after moderation, conflicting payload, concurrent duplicate creation, dependency rollback and compatibility with pre-scanId hashes. |
| Evidence and private MinIO | EvidencePolicy validates signatures/MIME, 10 MiB limit, five active files and duplicate hashes. Backend authorizes every download/delete. ExternalInfrastructureTests uploads actual PNG bytes, downloads exact bytes, proves anonymous 403, soft-deletes and verifies physical object purge in real MinIO. |
| Pending queue and moderation | Independent JWT role checks in Report-Service and Gateway. Required version and note; start-review, verify, reject, request-info and owner resubmit. Workflow/security tests cover invalid state, stale version, simultaneous decisions, terminal immutability, self-review and role spoofing. |
| Audit and outbox events | History and lifecycle events commit with state. Publisher retries the same event ID, preserves per-report order using a database sequence and never publishes raw case input or object keys. Tests cover clock reversal, retries, populated migration upgrade and actual ordered Kafka delivery. |
| Metrics | baotin_report_total increments after commit only; retries and rollback are tested. baotin_outbox_pending_total reads the durable pending queue. Collector/export and alert provisioning belong to the deployment. |
| Schema ownership and migration | Report owns only report schema, no cross-schema FK/queries. Versioned additive migrations retain published V1. Docker integration runs with a separate migration identity and a restricted runtime role; forbidden CREATE and cross-schema SELECT are rejected. Threat integration preserves existing target IDs and shares scan normalization. |
| Backend/frontend via Gateway | Explicit public report/moderation routes, JWT authorization, Idempotency-Key CORS and evidence-specific multipart bound. Full Gateway suite: 31 passes with real Redis. Frontend reuses upstream Auth/Notification client and design, with real picker, download/share, retry/error/loading and conflict handling. |
| Frontend verification | Typecheck, 46 unit tests, Web/Android/iOS exports; 20 report browser fixtures at 320/375/414/768/1440. Existing demo suite: 54 passes and six viewport-specific skips. Fixtures prove client behavior; they are not a claim of a deployed full-stack system. |
| Contracts and pushes | Report OpenAPI, internal target OpenAPI and lifecycle event schema are in Contracts. Twelve contract tests validate compatibility and paired source fields. Changes are pushed to feature/report-evidence-moderation in Report-Service, Threat-Service, API-Gateway, Contracts and Frontend. |

Commands: `gradlew test integrationTest bootJar` (JDK 21; Docker for integrationTest), frontend commands in REPORT_INTEGRATION.md, and `python -m unittest discover -s tests` in Contracts after installing its requirements.

Deployment acceptance: provision external credentials/TLS/ACLs and private bucket policy, review migration lineage, then run the environment smoke flow. Cross-team Reputation/Notification/Analytics consumer inbox/DLT and physical-device picker/share acceptance remain with the deployment integration. No production rollout or merge to protected main is claimed here.
