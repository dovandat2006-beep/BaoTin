# Report/Evidence integration

Verification after merging current Auth/Notification/Scan main: 46 unit tests pass; existing demo browser suite has 54 passes and 6 viewport-specific skips; 20 report browser fixtures cover create/upload, moderation and carrying scan input into a report at 320/375/414/768/1440. Typecheck and Web/Android/iOS exports pass. Browser tests use installed Chromium via BAOTIN_TEST_CHROMIUM because the pinned browser download was unavailable on this host. These are HTTP fixtures, not live full-stack proof.

Audience: reporting users and authorized moderators. Job: submit an actionable case, collect evidence, inspect and decide it. Mode: Operate. Preserve the existing Roboto/Material Teal workbench, desktop side rail, mobile bottom navigation, dark theme and semantic status tokens. No replacement visual identity.

The report surface is `src/screens/ReportWorkspace.tsx`. Its primary action creates a case, then exposes evidence controls within the saved case. Queue filters and case details share a screen; history and required decision notes make decisions reviewable. Empty/loading/error/retry states are explicit. File deletion requires a second confirmation press. Buttons use existing components/tokens and wrap as groups on narrow screens. The existing mock ReportsScreen remains available in default demo mode; setting EXPO_PUBLIC_API_URL enables the real report workspace.

HTTP owner contract: create, own list, detail, evidence POST/GET/DELETE and resubmit. Moderator contract: queue/detail/evidence GET and start-review/verify/reject/request-info POST. All requests traverse API Gateway. Multipart deliberately omits a manually set Content-Type so the runtime supplies its boundary. Failed creation keeps its UUID key for an identical retry; changed draft receives a new key. Evidence is uploaded separately so a failed attachment never silently recreates the case.

Auth flow consumes real server tokens and `/auth/me`, never a locally selected role. Native refresh uses SecureStore; web refresh uses HttpOnly cookie plus CSRF. A 401 attempts one serialized refresh; persistent 401 clears the session and unmounts report state. Backend enforces owner isolation and moderator authority independently. Password/MFA login is supported; SSO remains a separately documented unconnected flow.

Proof is split deliberately: frontend fixtures test layout/API behavior with explicit fixture credentials, while backend tests use real signed JWT and PostgreSQL. Neither is described as a live full-stack deployment. For report browser fixtures, build with EXPO_PUBLIC_API_URL=http://127.0.0.1:4184 using `npx expo export --platform web --clear --output-dir dist-api`, then run `npx playwright test -c playwright.reports.config.ts`. Default browser tests retain demo mode. Run `npm run typecheck`, `npm test`, `npm run build:web`, `npm run test:e2e`; native exports compile both platform bundles. Device picker/share and secure storage still need physical-device acceptance.

Clear the Expo export cache when switching EXPO_PUBLIC_API_URL between demo and API mode; otherwise cached bundles can retain the previous mode. Latest main notification deep links and watchlist behavior are preserved.

The live scan report action forwards the original user input and target type into an editable draft. Authenticated server scan UUIDs are carried as optional source references and verified by Threat; guest/demo scan IDs are omitted. A guest can log in and submit the carried input as a manual report. Editing the target clears its source reference. Logout/session expiry clears any pending target. Scan and history reuse the same authenticated/guest Gateway client while its cancellation and timeout behavior are preserved.
