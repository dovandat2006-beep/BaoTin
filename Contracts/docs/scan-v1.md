# Scan integration v1

Threat owns `threat.targets`, `scan_history`, `scan_urls`, rate limits and outbox. It never reads another schema. Text scans do not create permanent MESSAGE_TEMPLATE targets; template normalization is available for the future report-owned flow. URL identity is SHA-256 of the sanitized canonical URL. Private input hashes use HMAC with a separate deployment key. URL query order and repeated query keys remain significant; scheme/hostname/default ports/unreserved escapes/dot segments are canonicalized; fragments, userinfo, known credentials and tracking keys are removed. Lexical scanning never fetches the scanned URL.

POST routes accept guest or signed user access JWT. Invalid supplied bearer tokens always fail; forged user headers never create history. Guest quota is lower. Gateway must strip incoming `X-BaoTin-Client-IP` and set its verified client address; Threat only trusts this header from configured exact gateway peers. Direct callers are bucketed by socket address.

Scores use the master-plan weights. Missing components are omitted and remaining weights renormalized. URL model risk is the sum of all five phishing class probabilities. Text with URLs uses the maximum embedded URL score. At most five distinct links are analyzed, with `EMBEDDED_URL_LIMIT` when truncated. Missing AI is explicit (`aiAvailable=false`, warning); fallback never fabricates a model label/version/confidence. It cannot certify an input safe.

History is authenticated subject-only. Every detail/delete query includes user_id; a foreign ID returns 404. Snapshot contents do not change with current reputation. Raw text is not retained by default, previews are fully redacted. Optional raw retention is AES-256-GCM with scan UUID as AAD and expires after 30 days; cleanup nulls ciphertext. No raw text enters event payloads or logs.

`baotin.scan.events.v1` uses a transactional outbox, aggregate UUID as Kafka key, stable eventId, and broker acknowledgements before PUBLISHED. Crash after broker ack can redeliver the same eventId; consumers MUST deduplicate. Retry backoff is bounded; after 10 attempts FAILED is retained for operator review. Kafka is not in the synchronous scan path.

Optional Reputation adapter now uses the published `openapi/reputation-service.yaml`: GET `/internal/v1/reputation/targets/{threatTargetId}`, reads `finalScore` and verifies the returned target ID. Threat first looks up its existing canonical URL target ID; new targets have no existing score. The current Reputation contract requires a private Auth-issued ADMIN/MODERATOR access JWT. Configure/rotate it externally as REPUTATION_SERVICE_TOKEN; never forward a guest/user token or embed this credential in the website. 404 means unknown target; 401/403/other errors/timeouts mean unavailable, never zero reputation. Automatic service-credential issuance remains owned by Auth/platform integration.

Gateway catalog must allow only POST `/api/v1/scans`, `/api/v1/scans/text`, `/api/v1/scans/url` anonymously, and authenticated GET/DELETE history routes. Never expose inference endpoints. UI consumes server scores/snapshots and displays degraded results explicitly.

For compatibility with the newly published Reputation consumer, each URL scan also enqueues `threat.updated` on `baotin.threat.events.v1`, matching `events/threat/threat-reputation-events-v1.schema.json`. It carries target UUID/type, lexical ruleSignal and non-benign aiSignal (0..100) when present. Missing AI omits aiSignal so an outage cannot overwrite a previous known signal with zero. This is additional to Scan v1 events, uses the same transactional outbox, and does not create permanent targets for raw text.
